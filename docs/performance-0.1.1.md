# 0.1.1 性能与对话体积

## 测量方式

同一台Windows机器、Node24.21.0，使用临时合成SQLite库，无真实账号、模型调用、网络或用户历史。逻辑时间固定为2026-10-24 12:00（UTC+8）。每项预热3次，再取12次样本；表中为中位数。旧版运行代码来自已发布0.1.0源码归档，新旧使用同一份基准脚本。

规模：5万条隐私指纹、1万条私密上下文标记、2000位联系人、2万条私信/发送记录、2万条学习变更。记录原始数值见[性能数据](performance-0.1.1.json)。

| 操作 | 0.1.0 | 0.1.1 |
| --- | ---: | ---: |
| 隐私片段检测 | 359.151ms | 3.066ms |
| 私密上下文状态（缓存命中） | 15.017ms | 0.013ms |
| 联系人/私信面板状态 | 54.010ms | 8.002ms |
| 完整面板状态请求 | 153.722ms | 17.566ms |
| 300段字幕任务提示 | 16943字符 | 11258字符 |

这些是指定合成负载的单次基准样本，会随硬件、系统负载、数据分布及缓存状态变化；不代表DSH整体启动、模型推理、平台网络或真实界面响应时间，也不是对所有场景的加速保证。字符数减少约34%，未声称同等比例节省模型token。

## 改动

- 隐私指纹通过覆盖索引逐个精确查找，不再每次把最多5万条哈希载入JS。比对长度和收件人/账号排除规则保留。
- 隐私元数据通过本连接变更计数与其他连接的数据版本失效；事务内不缓存未提交视图，回滚不会留下错误的“可外发”状态。没有缓存允许发送的判断。
- 旧隐私历史补录在事务中完成且只执行一次；新的指纹写入使用可嵌套保存点合并磁盘提交。
- 每次联系人状态查询只生成一次排名；补充私信计数、主动消息类别、学习档案和最近事件索引。
- 绑定检查只读取会话头，避免复制原对话的全部事件；实际模型结果核对仍读取对应事件。
- 日窗口按时区和有效区间缓存，返回独立对象，保留午夜、回拨、时区变更和夏令时规则。

## 汇总对话精简

字幕结构由重复的`{from,to,text}`对象改为声明列名的`[from,to,text]`元组，保留每一段内容及时间戳。输入资料集中为JSON代码块；减少重复状态说明与空学习字段。输出只请求一份紧凑JSON，摘要/评价各建议100字以内，不在块外再重复点评。原解析器继续接受旧版结果，完整日终汇报仍按原设置生成。

当前宿主接口没有采用“完整内容只传模型、界面只显示摘要”的独立字段。本版没有隐藏全部机器数据、删除旧对话、擅自压缩历史，或省略模型评价所需的原文。真实模型对新提示的遵从效果仍需桌面加载后观察。

## 复测

源码目录运行：

```powershell
node scripts/benchmark.mjs benchmark-result.json
node --test --test-concurrency=1 tests/performance.test.mjs
```

新增测试覆盖跨连接缓存失效、新指纹长度、事务/保存点回滚、收件人和账号边界、一次性迁移、排名等价、会话事件惰性读取、夏令时及紧凑字幕完整性。

性能优化不改变无工具预设、隐私审核、配额、冷却和未知不重发规则，也没有增加操作系统级隔离。

最终完整回归为272项Node和113项Python通过。过程中前版安装器的即时PID断言曾间歇失败，15次心跳探针未发现停止后继续工作；安装器实现与原断言均未改动，最终完整原生串行回归通过。该观察未确认竞争的精确根因，不能据此宣称已修复所有进程回收竞争。
